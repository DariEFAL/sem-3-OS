## Требования
#### Цель работы
Приобретение практических навыков диагностики работы программного обеспечения.  
#### Задание
Необходимо выбрать стороннее ПО (возможные варианты ПО указаны ниже) и составить профиль его системных вызовов. Профиль составляется при помощи средств диагностики, указанных ниже в зависимости от выбранной операционной системы. Профиль должен содержать группы найденных системных вызовов и указания функционала ПО для чего они вызывались.  

Данная лабораторная работа носит сквозной характер в рамках курса. При выполнении последующих лабораторных работ необходимо продемонстрировать ключевые системные вызовы, которые в них используются и то, что их использование соответствует варианту ЛР.  

Итоговый отчет по данной работе формируется по завершении всего цикла лабораторных работ и должен включать сводную аналитику применяемых системных вызовов в рамках пройденного курса.

### Причины отправления на доработку: 
* Наличие зомби-процессов после завершения программы, зависания, взаимоблокировки (deadlocks), состояния гонки (race conditions) и другие артефакты неправильной синхронизации. 
* Неудаленные ресурсы операционной системы после их использования (очереди сообщений, сегменты памяти и т.д.). 
* Игнорирование кодов возврата системных вызовов.

### Поскольку курс посвящен системному программированию, к коду предъявляются следующие инженерные требования:  
* Обработка ошибок: Каждый системный вызов (fork, malloc, CreateProcess, mmap и т.д.) может завершиться ошибкой. Программа обязана проверять код возврата и корректно завершаться с выводом сообщения об ошибке (например, через perror() или GetLastError()), а не падать молча.
* Управление ресурсами ОС: Все выделенные ресурсы должны быть освобождены. Файлы — закрыты, динамическая память — очищена, дескрипторы (handles) — закрыты. Программа должна корректно дожидаться завершения дочерних процессов (wait/waitpid), а потоки должны быть синхронизированы (join) или отсоединены (detach).
* Модульность: Запрещается писать весь код в одном файле main.c, если объем программы становится громоздким. Логика должна быть разделена на заголовочные (.h) и исходные (.c/.cpp) файлы.
* Среда сборки: Проект должен собираться автоматизированно (использование Makefile или CMake).
* Использование API: Требуется использовать нативные системные примитивы (POSIX API для Linux, Win32 API для Windows). Запрещается использование высокоуровневых библиотек и фреймворков (Boost, Qt и т.п.), скрывающих логику работы с ОС (допускается использование базовых конструкций стандартной библиотеки языка, например, std::string исключительно для удобства работы с текстом/путями), если иное не оговорено в задании.

### Отчет
В конце всех лаб нужно будет сдать отчет. 
* Структура отчета: Титульный лист, цель работы, краткое описание архитектуры решения, листинг ключевых фрагментов кода, результаты работы (скриншоты терминала/логов), выводы.  
* Правило листинга: Помещаются только значимые для работы части кода. В отчет выносятся только архитектурно важные функции (например, функции инициализации IPC, обработки сигналов, работа с памятью).  
* Подтверждение работоспособности: Скриншоты или логи должны однозначно доказывать, что программа работает согласно заданию. Для многопроцессных/многопоточных программ требуется отображение PID/TID в консольном выводе для демонстрации конкурентного выполнения.

Примерный сценарий, для которого буду ловить системные вызовы:
1) Открыть nano для test.txt
2) Напечатать sudo apt update + 2 enter
3) скопировать cntr+c sudo apt update и вставить
4) вырезать с помощью cntr+K последнюю строку. вставить с помощью cntr+U в последнюю строку - 2 раза
5) сохранить (cntr+O, enter)
6) вырезать с помощью cntr+K первую строку (cntr+K)
7) сохранить (cntr+O, enter)
8) вырезать все остальное
9) cntr+X, enter

```bash
# cd sem-3-os-lab-1
strace -C -f -o ./files/01_nano_trace.txt nano ./files/00_test.txt

# теперь в файле nano_trace.txt и выводы системных вызовов, и сводка. Сводку вставляем в файл summary.txt
# Но хочу еще распределение по категориям вызовов. Поэтому прошу печатать только системные вызовы 
# с категорией file
strace -f -e trace=%file -o ./files/05_only_files.txt nano ./files/00_test.txt
# c категорией signal

strace -f -e trace=%desc -o ./files/07_only_desc.txt nano ./files/00_test.txt

ano ./files/00_test.tx

strace -f -e trace=\!file,signal,desc,process,memory -o ./files/15_other.txt nano ./files/00_test.txt
```


#### Профиль системных вызовов для nano:
* Основная сводка по всем командам в файле summary.txt

Я разделю все системные вызовы на группы:  
1) Запуск и загрузка: execve, brk, mmap, access  
2) Работа с файлами через путь: openat, access, newfstatat, unlink, readlink, getcwd, getdents64  
3) Работа с файлами через дескрипторы: read, write, close, fstat, lseek, fcntl, pread64, fsync  
4) Терминал (интерактивный ввод/вывод) poll, ioctl, read(0, ...), write(1, ...)  
5) Сигналы rt_sigaction, rt_sigprocmask  
6) Процессы и идентификация  getpid, getuid, geteuid, getgid, getegid, setfsuid, setfsgid, uname  
7) Работа с памятью mmap, munmap, mprotect, brk  
8) Многопоточность и рантакйм rseq, futex, set_robust_list, set_tid_address, prlimit64, getrandom  
9) Сеть / локальные сокеты  socket, connect
